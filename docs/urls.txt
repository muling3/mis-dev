MIS — local URLs cheat-sheet
(printed by `make urls`)

Service URLs (direct on host port + via Kong proxy on :8000).
Run a service from its OWN repo clone (`make dev` there); Kong routes to it:

  Auth          http://localhost:3001/api/auth/health        http://localhost:8000/api/auth/health
  Registration  http://localhost:3002/api/registration/health http://localhost:8000/api/registration/health
  Case          http://localhost:3003/api/cases/health        http://localhost:8000/api/cases/health
  Sandbox       http://localhost:3004/api/sandbox/health       http://localhost:8000/api/sandbox/health
  Notification  http://localhost:3005/api/notifications/health http://localhost:8000/api/notifications/health
  Document      http://localhost:3007/api/documents/health     http://localhost:8000/api/documents/health
  Admin         http://localhost:3008/api/admin/health         http://localhost:8000/api/admin/health

  (3006 is unassigned — the reporting service was retired.)

Infra UIs / endpoints:
  Kong proxy    http://localhost:8000
  Kong admin    http://localhost:8001
  Kong metrics  http://localhost:8100/metrics
  Postgres      localhost:5432   (user mis / pass mis, db mis_dev)
  Mongo         localhost:27017  (replica set rs0)
  Redis         localhost:6379
  Kafka         localhost:29092  (PLAINTEXT_HOST listener)
  MailDev SMTP  localhost:1025   (point SMTP_HOST/SMTP_PORT here in dev)
  MailDev UI    http://localhost:1080  (every captured email)
  Cuckoo REST   http://localhost:8090  (sandbox-svc polls; only up with `--profile cuckoo`, needs /dev/kvm)

Notes:
  - Kong reaches host services via host.docker.internal (host-gateway
    mapping in docker/docker-compose.yml).
  - strip_path is OFF: each service owns its real /api/<domain> path
    (NestJS app.setGlobalPrefix), so /api/auth/health -> :3001/api/auth/health.
  - A domain whose service isn't running returns 502 from Kong.
